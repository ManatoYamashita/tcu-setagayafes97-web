# Accessページ デザイン・実装方針

## 目的

来場者が会場所在地と推奨経路を短時間で把握し、迷わず外部地図へ移動できるAccessページを提供する。

## 情報の優先順位

1. 会場名・住所・Google マップへの導線
2. 推奨経路（尾山台駅から徒歩）
3. バスによる代替経路
4. 駐車場・駐輪場・混雑に関する注意
5. 当日用キャンパスマップの公開状況

## UIルール

- キーボードフォーカスは `focus-visible:outline-3 focus-visible:outline-offset-3 focus-visible:outline-primary-600` を基本とし、`ring-white` や低コントラストの半透明リングは使わない。マウス操作時に不要なリングを表示しないため、`focus-visible:` を使う。
- Heroは他セクションページ（`/events`・`/timetable`・`/info`など）と共通の`PageSheetLayout`（内部で`PageHero`を描画）を使用し、Access専用のHeroコンポーネントは持たない。
- 初期表示ではHero画像、Heroコピー、本文シートの順に入場させる。本文は地図、経路案内、注意事項、キャンパスマップの各要素がビューポートへ入った時に一度だけ発火する。
- Accessページの入場モーションは`AccessPageMotion`へ集約し、Server Componentの本文側は`data-access-reveal` / `data-access-stagger`だけで演出対象を宣言する。
- `prefers-reduced-motion: reduce`またはJavaScript無効時は初期状態を隠さず、静的な完成形を表示する。
- Heroの画像・英字サブラベルは`src/data/page-heroes.ts`の`access`エントリを唯一の出典とし、見出しと説明のみロケール別文言（`introduction.title` / `introduction.description`）で上書きする。多言語ページで日本語が固定表示されないようにするため。
- 交通案内動画はHeroではなく「会場までの行き方」セクションの導入として本文内に置く。
- 交通案内動画の上には会場名や徒歩時間のフローティングカードを重ねない。また、端をぼかすグラデーションも重ねない。全幅Heroではなく本文内の独立したブロックとして置くため、境界は矩形のまま示す。
- 交通案内動画は`public/videos/access-tcu-setagaya.webm`を使用し、装飾目的として無音で1回だけ自動再生し、再生後は最終フレームで停止する。
- 動きを減らす設定では動画を読み込まず、`public/images/video-posters/access-tcu-setagaya.webp`を表示する。
- 動画領域は16:9の表示比率を予約し、読み込み時のレイアウトシフトを防止する。ファーストビュー外のため`priority`は付けない。
- 動画・ポスター画像はいずれも16:9（1920×1080 / 1280×720）なので、表示枠のアスペクト比はブレークポイントを問わず16:9のまま変更しない。`2/1`など別比率にすると`object-cover`で経路イラストの上下が欠ける。
- 動画は装飾であり本文の主役ではないため、本文カラム幅いっぱいには広げず`max-w-3xl`で中央寄せに収める。
- Google マップ・大学公式案内への主要CTAは所在地セクション内に置き、テキストを伴うリンクとして44px相当以上の操作領域を確保する。
- 主要CTAのラベルは途中で折り返さない。
- 経路一覧は意味のある順序付きリストで表現する。
- 経路案内は「電車」「バス」のタブで切り替える。WAI-ARIAのTabsパターン（自動アクティベーション、roving tabindex、矢印キー・Home・End対応）に準拠する。
- 非アクティブなタブパネルは条件レンダリングで消さず`hidden`属性でDOM上に残し、JavaScriptが動作しない環境でも全経路を読めるようにする。この制約上、`role="tabpanel"`の要素自体にdisplay系ユーティリティを付けない。
- 経路カードは電車・バスで共通の縦タイムライン（出発ノード→区間→到着ノード）で表現し、白カード3枚グリッド（`grid gap-4 sm:grid-cols-2 lg:grid-cols-3`）のレイアウトは維持する。1カラム化しない。
- タイムラインの縦線は各ステップが「自分の下側の区間」だけを描く。先頭ノードの上と末尾ノードの下に線を出さないため、カード全体を貫く絶対配置の通し線は使わない。
- ノードは出発＝塗り丸、経由＝白抜き丸、到着＝二重丸で区別する。乗車区間は`primary-600`の実線、徒歩区間は`gray-400`の点線で描き分ける。
- 路線番号は`primary-600`背景・白文字の角丸ピルで表示し、紫は路線番号・ノード・バッジなど差し色としてのみ使用する。
- おすすめ経路のカードは枠線を`border-2 border-primary-600`にし、「おすすめ」バッジを枠線の右上へ絶対配置で重ねる。バッジをカード内のフローに置くとタイムラインの開始位置が他カードとずれるため、必ず`absolute`で浮かせる。
- 丸と線は装飾なのでレール列ごと`aria-hidden`にし、経路情報は必ずテキストで持つ。
- タイムラインはカード内の入れ子`<ol>`とし、各`<li>`に「ノード名＋そのノードから出る区間」をまとめて読み上げ順を経路順に一致させる。
- `display:grid`を当てたリストにはリストセマンティクス維持のため`role="list"`を付ける。
- 白背景に載せる紫は`primary-600`以上を使う。ブランドカラーの`primary-400`は白文字とのコントラスト比が不足する。
- `@theme`に定義がない`primary-800`・`gray-300`・`gray-500`は使用しない。灰色は`gray-200`（罫線）・`gray-400`（点線）・`gray-600`・`gray-700`から選ぶ。
- 地図iframeには内容が分かる`title`を付け、遅延読み込みする。
- 色だけに依存せず、アイコン・見出し・説明文を併用する。
- モバイルでは徒歩時間や乗車時間を本文の下へ自然に折り返す。
- 外部地図が利用できない場合でも、住所と経路情報だけで来場判断ができる構造にする。
- 所在地欄は地図と住所を罫線で簡潔に区切り、装飾アイコン、英字ラベル、カード状の影を使用しない。

## コンテンツ管理

- 住所、交通経路、地図URL、表示文言は`src/data/access.ts`へ集約する。
- 交通経路は東京都市大学公式の交通案内を基準とする。
- ただし徒歩時間はHero路線図イラストの表記を正とする（尾山台駅=15分、等々力駅=20分）。大学公式案内の尾山台駅「徒歩12分」より実際の所要時間に近いため。いずれにも根拠がない駅は概算である旨をコードコメントに残す。
- バス経路は`operator`・`lineCode`・`destination`に分解して保持し、表示文言はUI側で組み立てる。構造化済みの情報を`description`で重複させない。
- 経路データの表示文字列は`LocalizedText`（`Record<Locale, string>`）で4ロケール分を持つ。所要時間などの数値はロケール非依存なので重複させない。
- 駅名・バス停名・路線名は`stationNames`・`busStopNames`・`lineNames`の定数へ集約して参照する。同じ駅が乗車駅とバスの行き先の両方に現れるため、直接リテラルを書くと訳が割れる。
- バスの系統番号（`lineCode`）は翻訳しない。車体や停留所の表示と照合するための記号であり、訳すと現地で照合できなくなる。
- ロケールの解決はサーバーコンポーネント側（`resolveTrainRoutes` / `resolveBusRoutes`）で行い、クライアントコンポーネントには解決済みの文字列だけを渡す。4ロケール分の文字列をRSCペイロードへ載せない。
- 「◯◯ゆき」のような行き先表記は言語で語順が異なるため、`{destination}`プレースホルダー付きテンプレート（`directions.destinationLabel`）として4ロケール分持つ。
- 会場名は`location.venue`を単一の出典とし、経路タイムラインへはプロパティで渡す。同義の文言キーを新設しない。
- 駐輪場など未確定の情報は推測で公開せず、準備中であることを明示する。
