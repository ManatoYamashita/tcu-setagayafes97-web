# 文節での改行（BudouX）

サイト内の日本語は **どのブラウザでも文節の境目でだけ改行する。**
`word-break: auto-phrase` は Chrome にしか無く、iOS（WebKit）・Firefox では漢字の間のどこでも
改行可能になる。そこへ `text-balance` が行長を揃えにいくと、「東京都市大 / 学」のように語の途中を選ぶ。

## 仕組み

| 部品                                                          | 役割                                                                                           |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `PhraseBreaker`（`src/components/layout/`、ルートレイアウト） | ハイドレーション後の空き時間に BudouX を読み込み、`<body>` 以下の日本語テキストを処理する      |
| `breakPhrasesIn()`（`src/lib/phrase-break-dom.ts`）           | テキストノードの文節の境目へ U+200B（ゼロ幅スペース）を入れ、親へ `data-phrase-break` を付ける |
| `globals.css` の `[data-phrase-break]`（`@layer base`）       | `word-break: keep-all` で境目以外の改行を禁じ、`overflow-wrap: anywhere` ではみ出しだけ防ぐ    |
| `src/lib/budoux-ja.ts`                                        | パーサーと日本語モデルだけを読む（gzip 約 9 KB。動的 import なので初期チャンクに入らない）     |

- **`<wbr>` ではなく文字を差し込む。** React が持っているテキストノードを分割すると、
  次の更新で React が先頭の断片だけを書き換え、文字列が壊れる
- 以後の差し替え（画面遷移・絞り込み・Webhook による再検証）は `MutationObserver` で追う。
  React がテキストを書き換えると区切りは消えるが、同じ経路で入れ直される
- 対象外: `lang` が `ja` 以外の範囲（多言語ページ）、`textarea` / `select` / `code` / `pre` / `svg`、
  `aria-live`（書き換えると読み上げが繰り返される）、`[data-no-phrase-break]`
- コピーした文字列からは区切りを取り除く（住所の貼り付けなどに不可視文字を持ち出さない）
- 要素側に `[word-break:auto-phrase]` などの明示指定があれば、そちらが勝つ（base 層に置いている理由）

## ハイドレーション前に書き換えない

**遅れてハイドレーションされる `<Suspense>` 境界の中身を先に書き換えると、React がエラー #418 を出して
境界を描き直す**（2026-10-10、`/events` の本番ビルドで実測）。`breakPhrasesIn()` は最寄りの
`__reactFiber$…` を持つ祖先を探し、ハイドレーション済みのテキストだけを処理する。
見送ったテキストは 500ms 間隔で最大 20 回まで歩き直す（ハイドレーションは DOM を変えないため
`MutationObserver` では気づけない）。

- 持ち主が親でなくても、`dangerouslySetInnerHTML` の中身（microCMS の本文）は React が照合しないので処理する
- **React の内部名に頼っている。** React を上げたら、下の検証をやり直すこと

## DOM を作り替える演出の前に呼ぶ

SplitText のように DOM を作り替えた後の要素には React の持ち主がいないため、`PhraseBreaker` は触れない
（見送りが続き、上限で諦める）。**分割の前に `applyPhraseBreaks(要素)` を await し、
区切り文字 `PHRASE_SEPARATOR` を `wordDelimiter` に渡す。** 例は `ChairpersonSection` のテーマ解説。

実測（2026-10-10、`/about` のテーマ解説の行）:

| 幅     | 変更前（1文字単位で分割）                       | 変更後（文節単位で分割）                                              |
| ------ | ----------------------------------------------- | --------------------------------------------------------------------- |
| 390px  | `…共通テーマには、これま` / `で両キャンパスが…` | `…共通テーマには、` / `これまで両キャンパスが積み上げてきた` / …      |
| 1280px | 同様に語の途中で折れる                          | `…共通テーマには、これまで` / `両キャンパスが…歴史や伝統を大切に` / … |

## 検証（2026-10-10、本番ビルド + Chromium）

- 14 ルート × 320 / 390 / 1280px × 3 周（126 回の読み込み）で、コンソールエラー 0・横はみ出し 0
- `pnpm test:e2e` 72 件成功
- お知らせの `h1`（`/info/toshi-music`、390px）: `auto-phrase` を外した WebKit 相当では
  `…東京都市大` / `学　第97回世田谷祭` / `『TOSHI…』`、`keep-all` + 区切りでは
  `…東京都市大学　` / `第97回世田谷祭` / `『TOSHI…』`
- **iOS Safari の実機では未確認。** この環境に WebKit が無い

## 既知の制約

- 区切りが入るのはハイドレーション後なので、Safari では表示直後に一度だけ改行位置が変わることがある
- お知らせのタイトルの `UnbreakableText`（[typography.md](./typography.md)）は、JS が動く前の Chrome で
  「第 / 97回」と割れるのを防ぐために残している
