# `/events` の無限スクロールと絞り込みの追従

`/events` の一覧はページ分割をやめ、末尾に近づくと継ぎ足す方式へ移行した（#239）。
同時に絞り込みを `position: sticky` で画面内へ留めている。

関連: [events-search.md](./events-search.md)（検索と絞り込みの中身） /
[static-html-and-search-params.md](./static-html-and-search-params.md)（`<Suspense>` 境界の制約） /
[layout-e2e.md](./layout-e2e.md)（実ブラウザの再発防止装置） /
[../dev/testing.md](../dev/testing.md)（検証の層分け）

## 何が問題だったか（2026-09-20 実測）

| 項目                       | 値                                      |
| -------------------------- | --------------------------------------- |
| 公開企画数                 | **98件**（`EVENTS_PER_PAGE` = 12）      |
| 総ページ数                 | 9                                       |
| 最後まで見るのに必要な操作 | **8クリック + 8回のフルナビゲーション** |
| `lg` 未満の絞り込みの位置  | ページ最上部（固定なし）                |

`lg` 未満では、**2枚目のカードを過ぎた時点で絞り込みが画面外へ消える。**
条件を変えるにはページ先頭まで戻る必要があった。

### ページ分割の撤去でSEOは損なわれない

旧 `Pagination` は `<button onClick={router.push}>` であり **`href` を持たなかった。**
クローラーは元から2ページ目以降へ到達できておらず、13件目以降の発見経路は
`sitemap.xml`（97件）だけだった。したがって撤去による損失は発生しない。

**静的HTMLへ載る12件は `<Suspense>` の fallback 由来であり、移行後もそのまま残っている。**

## 構成

| ファイル                                      | 役割                                                         |
| --------------------------------------------- | ------------------------------------------------------------ |
| `src/components/events/EventsContent.tsx`     | **クエリを読む唯一の場所。** 絞り込み後の全件を降ろす        |
| `src/components/events/EventsView.tsx`        | sticky な `<aside>` と一覧を組む。`key` で表示件数をリセット |
| `src/components/events/EventInfiniteList.tsx` | 表示件数の state / 監視 / ボタン / URL の書き戻し            |
| `src/lib/filters.ts`                          | `resolveVisibleCount()` — `?page=N` の解釈                   |

追加読み込みに**通信は発生しない。** `getEventsList(200)` がサーバー側で全件を降ろしており、
`EventInfiniteList` は手元の配列を `slice()` で伸ばしているだけである。

> [!IMPORTANT]
> **`EventsView` へページ分割済みの配列を渡してはいけない。** 表示範囲は
> `EventInfiniteList` が自分で決める。呼び出し側で切ると、その先が永久に読めなくなる。
> **この誤りは lint / 型 / ユニットテスト / build のどれにも引っかからない。**

## 設計判断

### 1. 監視は「発火したら即 `disconnect()`、`visibleCount` で張り直す」

1回のコールバックに複数エントリが載ることも、再監視までに続けて発火することもある。
`setVisibleCount` は関数型更新なので、そのぶん加算が累積して一気に全件展開される。

**切ったあと張り直す契機は `visibleCount` の変化ひとつしかない。**
`hasMore` と `loadMore` は継ぎ足しても値・参照ともに変わらないため、依存を
`[hasMore, loadMore]` にすると効果が二度と再実行されず、**1回だけ追加して永久に止まる**
（2026-09-20 実測。12件 → 24件 で打ち止めになった）。

そこで効果の打ち切り条件に `hasMore` ではなく `visibleCount >= total` を直接書き、
`react-hooks/exhaustive-deps` に依存を強制させている。

> [!WARNING]
> **格上げだけでは #239 そのものの形を止められない。** 打ち切り条件も依存配列も
> `hasMore` へ**揃えて**戻すと、依存は過不足なく揃っているため `exhaustive-deps` は
> 何も言わない（2026-09-20 実測。この形だけ exit 0 で通った）。`hasMore` は同じファイルに
> 定義済みで描画側でも使うため、「整理のつもりで効果の中も揃える」は自然に起こる。
> そこで `no-restricted-syntax` で、**効果と `useCallback` の中から `hasMore` を読むこと自体**を
> 禁じている。描画側の `{hasMore && ...}` は対象外。

`rootMargin` は `300px`。1回の追加で伸びる高さ（モバイル1列 約4,800px /
デスクトップ4列 約1,200px）より小さいため、新しいセンチネルが生成直後に
再発火することはない。**大きくしすぎると連鎖して全件が一気に開く。**

### 2. 「もっと見る」ボタンは装飾ではない

`IntersectionObserver` が発火しない経路が実在する。

- キーボードのみの操作（Tab でフォーカスは進むが、ビューポートが観測条件を満たすとは限らない）
- スクリーンリーダーの仮想カーソル移動（読み上げ位置は動いてもスクロールしないことがある）
- 省電力モード・拡張機能によるレンダリング抑制、`IntersectionObserver` 非対応環境

これらでは**ボタンが13件目以降への唯一の到達手段**になる。外してはいけない。

打ち止めでボタンが消えるとフォーカスが `<body>` へ落ちるため、**ボタン由来の追加で
全件に達したときだけ**完了メッセージへフォーカスを移す。自動追加では移さない
（読んでいる位置が飛ぶため）。

### 3. `?page=N` は「N ページ目」ではなく「N ページ分を展開して着地」

ページ分割の時代に配られたURL・ブックマーク・ブラウザバックを壊さないための後方互換。
`resolveVisibleCount()` が解釈する。

> [!WARNING]
> **範囲外を空にしてはいけない。** `page` は URL のクエリから検証なしに入る
> （`parseEventPage` の `Number(...) || 1`。`-1` は truthy なので素通りする）。
> ページ分割だった頃は範囲外を空配列として扱っていたが（#162）、無限スクロールで
> 同じことをすると `?page=-1` や `?page=999` が**カードの無い真っ白な一覧**になる。
> 常に最低1ページ分を返し、総件数へ丸める。

読み進めた位置は `window.history.replaceState(null, "", href)` で書き戻す。
**`router.replace()` は使わない。** ナビゲーションが起きて再描画とスクロール復元が走り、
継ぎ足しのたびに画面が跳ねる。

`EventsView` の `key` は `buildEventsQuery(filters)`（**`page` を含まない**）。
含めると継ぎ足すたびに一覧が作り直され、表示件数が12件へ巻き戻る。

## 絞り込みの追従（sticky）

| ブレークポイント | `top`                                       | 背景                      |
| ---------------- | ------------------------------------------- | ------------------------- |
| `lg` 未満        | `calc(var(--header-height) - 1rem)` = 72px  | `bg-white` + `-mx-4 px-4` |
| `lg` 以上        | `calc(var(--header-height) + 1rem)` = 104px | なし（カードは右カラム）  |

**`--header-height`（5.5rem = 88px）をそのまま使ってはいけない。** これはページ最上部の
ヘッダーの値であり、スクロール中のヘッダーはピル型へ縮んで**実高 77px** になる。
88px に置くと 11px の隙間が空き、そこをカードが通り抜けて見える
（2026-09-20 実測。`elementFromPoint` が `DIV.grid` を返した）。
72px まで上げてピル（`z-40`）の背後へ 5px 潜り込ませると隙間が消える。

`lg` 側で +1rem の余白を取れるのは、カードが右カラムにあり `aside` の背後を通らないため。

> [!IMPORTANT]
> **`self-start` は grid で必須である。** grid item の既定は `align-self: stretch` で、
> 高さが行全体（= カード群の高さ）まで伸びるため、**sticky が一度も貼り付かない。**
> 外した状態の実測（2026-09-20 / 1440x900）:
>
> | 指標                         | `self-start` あり | なし            |
> | ---------------------------- | ----------------- | --------------- |
> | `align-self`                 | `flex-start`      | `auto`          |
> | `aside` の高さ / 親の高さ    | 559 / 1587        | **1587 / 1587** |
> | 一覧表示中に画面外だった回数 | **0 / 17**        | **15 / 16**     |
> | `top` の範囲                 | 104〜171          | **-10629〜171** |
>
> **見た目は変わらないので、外すと静かに追従だけが失われる。**

`EventFilters` のルートに `max-h-[calc(100svh-var(--header-height)-2rem)] overflow-y-auto` が
要るのもこの追従とセットである。無いと、開いた瞬間にパネルが画面を縦いっぱいに占める。

## `<Suspense>` fallback ツリーの制約

`EventInfiniteList` は `EventsView` の配下にあり、`src/app/events/(list)/page.tsx` の
`<Suspense>` **fallback としても描かれる。** ここで `useSearchParams()` を呼ぶと
fallback 自身が bailout し、ページ本体が静的HTMLから丸ごと消える（#156）。

`eslint.config.mjs` の `EVENTS_FALLBACK_TREE` へ登録済み。
`useState` / `useEffect` / `useRef` と `window.history` は bailout を起こさないため使える。

fallback には**絞り込み後の全件**を渡している。描かれるのは先頭12件だけで、配列の参照が
`EventsContent` の `initialEvents` と同一なので Flight ペイロードにも重複して載らない。

### HTMLサイズ（`NEXT_PUBLIC_EVENTS_VISIBLE=true pnpm build`）

|                            | raw         | gzip -9    |
| -------------------------- | ----------- | ---------- |
| ページ分割（移行前の本番） | 298,696     | 41,538     |
| 無限スクロール             | **263,753** | **40,241** |

**増えていない。** fallback へ全件渡すぶんより、`Pagination` のマークアップが消えたぶんが勝つ。

| 一覧表示中に絞り込みが画面外       | **0 / 17**           | **0 / 62**       |
| 絞り込みの直上にカードが透けた回数 | **0 / 17**           | **0 / 62**       |

| 打ち止め後                         | ボタン消滅・完了表示 | 同左             |

| 操作                              | 結果                                                |
| --------------------------------- | --------------------------------------------------- |
| Tab のみで「もっと見る」へ        | 36回で到達。Enter で 12 → 24 件                     |
| 打ち止め後のフォーカス            | `<p>すべての企画（98 件）を表示しました</p>` へ移る |
| `?page=3` → 詳細 → ブラウザバック | 36件 / `?page=3` で復帰                             |

> **件数は「グリッドの子要素」で数えること。** `a[href^="/events/"]` を数えると 97 になる。

> その数え方から漏れる（`sitemap.xml` の内訳も企画 97 件＋著名人企画 1 件で合計 98 件）。

### なぜ実ブラウザの E2E を置かないのか

`/events` は microCMS を読み、`getEventsList()` は `isMicrocmsConfigured` が false のとき
`[]` を返す。**CI には secrets が無いため企画が0件になり、無限スクロールの E2E を置いても
「企画が無いまま緑」になる。** fail-open な検査は、無いより悪い。

そこで依存配列のほうを ESLint で縛った。縛りは2本組である。

1. `react-hooks/exhaustive-deps` の `error` 格上げ。この規則は**既定では warning であり
   `pnpm lint` を緑のまま通す**ため、`EventInfiniteList.tsx` に限って格上げしている
   （格上げ前に退行を注入し、warning 止まりで exit 0 になることを実測した）。
   止まるのは依存配列と本体が**食い違った**中間状態である。
2. `no-restricted-syntax` で、効果と `useCallback` の中から `hasMore` を読むことを禁じる。
   1 だけでは、打ち切り条件も依存配列も `hasMore` へ揃えて戻す形（**#239 そのもの**）が
   素通りする。依存が過不足なく揃ってしまうためで、2026-09-20 に実測して確認した。

下2つは現状どの自動検査にも掛からない。**目視でしか気付けない**ことを承知のうえで、
根拠をこのドキュメントとコード中のコメントに残している。
