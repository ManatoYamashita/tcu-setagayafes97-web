# 色の使用規約

Tailwind 既定パレットの扱い、紫の統一、残している非ブランド色相と、それを機械的に守る装置。
[design.md](./design.md) から分割した（2026-10-04、#389）。トークンの値は design.md、コントラストは [color-contrast.md](./color-contrast.md) にある。

---

## Tailwind 既定パレットを直接使わない

`@theme` に無い色名を書くと、**エラーも警告も出ないまま Tailwind 既定の値へ落ちる。**
既定のニュートラルは青みがかったスレートで、本プロジェクトの純中性ランプと混ざらない。

| 書いた指定 | 落ちる先（Tailwind 既定） | 本来あるべき値       | 何が起きるか                           |
| ---------- | ------------------------- | -------------------- | -------------------------------------- |
| `gray-500` | `#6a7282`（青み）         | `#717171`（中性）    | 中性ランプの中に1色だけ青い灰が混ざる  |
| `gray-300` | `#d1d5dc`（青み）         | `gray-200` `#d1d1d1` | 同上。しかも `gray-200` とほぼ同じ明度 |

**`gray-500` は欠番を埋めて解決した**（2026-09-19 / #179 B）。
`oklch(55%)` の実配信 `#717171` は輝度 0.1664 で、既定 `#6a7282` の 0.1671 と**ほぼ同一**である。
つまり**コントラストを一切変えずに色相だけ中性へ戻せる**。

> [!WARNING]
> **`text-gray-500` を `gray-400` へ機械的に置換してはいけない。**
> 白背景で `#6a7282` は 4.84:1 だが `#8f8f8f` は **3.23:1** で AA を落とす。
> 16箇所が一斉に未達になる。「トークンに寄せる」置換ほど、**寄せ先の比を先に計算すること。**

## 紫はすべて `primary-*` を使う

Tailwind の `purple-*` はブランドと**色相差 7.5–11.6°** しかなく、15° 未満は同一色として知覚される。
一方で彩度がブランドより約40%高いため、**「ブランド紫を出そうとして失敗した色」**に見える。

段は1対1で対応させる（`purple-500` → `primary-500`）。
2026-09-19 時点で `purple-*` / `violet-*` / `fuchsia-*` の直接使用は**ソースに1件も無い**。
**この状態は `eslint.config.mjs` の `no-restricted-syntax` が機械的に維持する**（後述）。

**同一グラデーションにブランド紫と別の紫を混ぜない。** `from-primary to-purple-600` は禁止。

## 残している非ブランド色相と、その理由

**比はいずれも `text-gray-900`（実配信 `#070707`）を載せたときの値**で、実配信 oklch から
算出した WCAG 2.1 の相対輝度比である。

> [!IMPORTANT]
> **バッジの既定配色が実際に描画されるのは、お知らせ一覧と記事詳細の2画面だけである。**
> そこに出るのは `urgent` / `news` / `other` の3種類にとどまる。
> 企画一覧と企画詳細は `tone="soft"` を渡すため、`Badge` の variant 別配色を参照しない
> （`src/components/ui/Badge.tsx` の `colorStyles`）。**この表を「画面で色分けされている根拠」として
> 読まないこと。** 実画面との乖離は #228 で追跡している。

| 色相                   | 残している用途                                                           | 理由                                                 |
| ---------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------- |
| `red-*`                | 緊急のお知らせのバッジ、フォームのエラー、ご来場の方への「緊急時の対応」 | **危険・エラーの意味**を担う。他の色では代替できない |
| `green-*`              | `room` バッジの既定配色                                                  | 分類の識別。`room` は **9.08:1**                     |
| `blue-*`               | お知らせのバッジ                                                         | 分類の識別。`news` は **5.35:1**                     |
| `orange-*` / `amber-*` | `stage` / `store` バッジの既定配色                                       | 分類の識別。**6.98:1 / 9.44:1**                      |
| `pink-*`               | `special` バッジの既定配色、委員会紹介の「97」の終点                     | 分類の識別。**5.62:1** / 「97」は **3.29:1**         |

**基準は「意味の異なる分類を一目で区別する」かどうかである。**
装飾のグラデーションや、単に紫の代わりに使われている色は対象外で、`primary-*` へ寄せる。

> [!NOTE]
> **例外は1つだけ。委員会紹介ページの「97」である。**
> 紫からピンクへ抜ける配色はサイト所有者の指定であり、分類用途ではないが残す。
> #179 B でいったん `from-primary-600 to-primary-700` へ倒したが、ピンクが失われるため
> 2026-09-19 に `from-primary-500 to-pink-500` へ戻した（`#9c50be` 4.47:1 →
> `#f6339a` 3.29:1、地色 `gray-50` `#f5f5f5`・60px/700 の要求 3:1 を両端で満たす）。
> **元の `from-purple-500 to-pink-400` には戻していない。** 終点 `pink-400` `#fb64b6` が
> 2.53:1 で未達、始点 `purple-500` は `eslint.config.mjs` が禁止しているため。
> **ここへ他のグラデーションを足さないこと。** 例外を増やすなら、なぜ分類用途でない色相が
> 要るのかをこの節へ書くこと。

**Tailwind の `purple-*` は分類用途でも使わない。** ブランドと色相差が 15° 未満で、
「ブランド紫を出そうとして外した色」に見えるためである。**分類色として紫が要る場合は
ブランドの `primary-*` を使う**。

## 規約を破れないようにしてある

上の3節は**文書だけでは守れない**。`@theme` に無い色名を書いても、Tailwind は
エラーも警告も出さずに既定パレットの値を出力するため、lint・型・ユニットテスト・build・
Layout E2E のすべてを通過したまま色だけがずれる。#179 の監査で見つかったときには
約50箇所まで広がっていた。

そこで `eslint.config.mjs` に `no-restricted-syntax` を1本置いてある。禁止するのは2種類。

| 禁止するもの                          | 理由                                                  |
| ------------------------------------- | ----------------------------------------------------- |
| `purple-*` / `violet-*` / `fuchsia-*` | ブランドと色相差 15° 未満。`primary-*` を使う         |
| `gray-300` / `gray-800` / `gray-950`  | `@theme` に無い段。既定の青みがかったスレートへ落ちる |

> [!IMPORTANT]
> **`@theme` へ段を足したら、この規則からその段を外すこと。** 足したのに禁止されたままだと、
> 正しい指定が lint で落ちる。逆に `@theme` から段を消したら、ここへ足す。

### コメントの中のクラス名 — ESLint の死角は別の検査が塞ぐ

**Tailwind のソース走査はテキスト走査であり、コードコメントの中のクラス名も
「使われている」と見なす。** 一方 ESLint の `no-restricted-syntax` が見るのは AST の
`Literal` と `TemplateElement` だけで、**コメントは対象外である。**
つまりガードの死角と Tailwind の感度がずれている。

2026-09-19 まで、`AboutHero.tsx` のコメントに説明として残していた
「旧グラデーションのクラス名」のせいで、**どこからも使っていない紫と桃の
ユーティリティ2本と対応する CSS 変数が、本番CSSへ出続けていた**（実測で確認）。
画面は壊れないが、消したはずの色が配信物に残る。

**この死角は [`scripts/assert-no-restricted-colors.mjs`](../../scripts/assert-no-restricted-colors.mjs)
が塞ぐ**（#230）。`Static Checks` から `pnpm check:colors` で走り、Tailwind の走査範囲の
**生テキスト**をそのまま見る。`git ls-files` 以外に何も要求しないので、同ジョブの
「`pnpm install` だけで完結する」性質も、**fork PR でも結果が出る**性質も壊さない。

|                                               | 見るもの                             | コメントが | 役割                        |
| --------------------------------------------- | ------------------------------------ | ---------- | --------------------------- |
| `eslint.config.mjs` の `no-restricted-syntax` | AST の `Literal` / `TemplateElement` | 見えない   | 禁止色を**書かない**        |
| `scripts/assert-no-restricted-colors.mjs`     | `src/` の生テキスト（追跡ファイル）  | **見える** | 禁止色が**配信CSSへ出ない** |

> [!IMPORTANT]
> **禁止リストの一次定義は [`scripts/restricted-color-tokens.mjs`](../../scripts/restricted-color-tokens.mjs)
> の1箇所で、上の2つが両方ともそこを読む。`@theme` へ段を足したら、そのファイルから外す。**
> 同じ正規表現を2箇所に置くと、片方だけ直して片方がすり抜ける。

落ちるのは**接頭辞を伴う形**だけである。色のユーティリティは必ず名前空間の接頭辞を持つため、
接頭辞の無い裸のトークンからは何も出力されない。**実測値を説明する表（「旧 `purple-500` は 3.78」）は
コメントに残せる。** 走査は接頭辞を列挙せずに判定するので、`hover:` や `md:` の変種も落ちる。

- **クラス名の形で書きたくなったら、接頭辞を外して書く。**
  「`from-purple-500`」ではなく「既定パレットの紫の500段」と書く
- 配信物そのものを確かめたいときは次を使う。**較正値が取れたことを先に確認する**のは、
  取得に失敗したときに「0 件＝異常なし」と読めてしまうのを防ぐためである（#230）

```bash
set -o pipefail
base=https://setagayafes.org
css=$(curl -fsS "$base/about" | grep -oE '/_next/static/chunks/[a-z0-9]+\.css' | head -1)
[ -n "$css" ] || { echo "CSSのURLを取得できませんでした"; exit 1; }
body=$(curl -fsS "$base$css") || exit 1
grep -q -- '--color-primary-400:#bf73e3' <<<"$body" \
  || { echo "較正値が無い。本体CSSではありません: $css"; exit 1; }
hits=$(grep -oE '[a-z-]+-(purple|violet|fuchsia)-[0-9]{2,3}' <<<"$body" | sort | uniq -c)
[ -n "$hits" ] && { echo "$hits"; exit 1; }
echo "残存ゼロ（本体CSS ${css}）"
```

**「何も出ない」を正常の合図にしない。** 残存ゼロなら最後の行がそう言い、
残っていれば内訳を出して終了コード 1 で終わる。取得に失敗したときも 1 で終わる。

> [!WARNING]
> **変数展開の直後に全角文字を置くときは `${css}` と書く。** `"$css）"` と書くと、
> bash が `）`（U+FF09）の先頭バイトまで変数名として飲み込み、**パスが消えて文字化けする**
> （macOS の bash 3.2 で実測。`en_US.UTF-8`）。出力が壊れるだけで終了コードは 0 のままなので、
> **「動いているように見えて壊れている」形になる。** この検査自体が防ごうとしている形と同じである。

退行を注入して赤くなることを実測した（2026-09-19）。

| 退行させた内容                                                | `pnpm check:colors`                  | `pnpm lint`      |
| ------------------------------------------------------------- | ------------------------------------ | ---------------- |
| コメントへクラス名を戻す（#230 が直した形）                   | **落ちる**                           | **通る**（死角） |
| `className` へ禁止色を書く                                    | 落ちる                               | 落ちる           |
| コメントへ**接頭辞なし**で書く（「旧 `purple-500` は 3.78」） | 通る（意図どおり）                   | 通る             |
| `globals.css` から `source(none)` を外す                      | **落ちる**（走査範囲を保証できない） | 通る             |
