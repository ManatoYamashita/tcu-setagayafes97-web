# 日本語専用ページを経由するときの言語保持

Issue #441。多言語ページの構成全般は [i18n-page-structure.md](./i18n-page-structure.md) を参照。

## 来場者の動作

- `/en/info/guide` → `/events` → `Access` は `/en/access` に戻る。zh / ko も同様。
- 多言語対応ページを開いたときはURLの言語を採用し、その言語を記憶する。
- 日本語専用ページでは本文と `<html lang>` は日本語のまま。共通ナビゲーションだけが記憶した言語になる。
- 「日本語」を選ぶと記憶を解除する。日本語専用ページでは同じページに留まり、多言語対応ページでは同じページの日本語版へ移る。
- 言語を選んでいない来場者は日本語のまま。ブラウザ言語からの自動選択は行わない。

## 記憶の場所と寿命

`src/i18n/locale-preference.ts` が `sessionStorage` の `setagayafes.locale` を管理する。
寿命はタブのセッションで、同じタブの再読み込みでは残る。`localStorage` やCookieには保存しない。
値は対応ロケールだけを受け入れ、日本語はキーの削除で表す。
保存先をブラウザが拒否した場合はメモリに保持し、そのページ読み込み内のクライアント遷移で使う。
この場合、再読み込みをまたぐ保持は保証しない。

`useSyncExternalStore` のサーバースナップショットは常に `null`。
サーバーHTMLとクライアントの初回描画はURLからロケールを決め、ハイドレーション後に記憶を読む。
共有ストアの購読でHeader / Footer / デスクトップ・モバイルの言語切替を同時に更新する。
ルートレイアウトで `cookies()` / `headers()` を読まず、既存のSSG/ISRを維持する。
`routing.ts` の `localeDetection: false` / `localeCookie: false` も維持する。

## URLと記憶の優先順位

`useCurrentLocale()` は `splitLocalePrefix()` で正規化したパスを使う。
`LOCALIZED_PATHNAMES` のページではURLを優先し、マウント後のeffectで記憶を更新する。
日本語専用ページでは記憶があればそれを使い、無ければ日本語へ倒す。
`HtmlLangSync` はURLだけを読む。日本語専用ページの本文を外国語と誤って宣言しないため。
共通ナビゲーションの翻訳部分には独立した `lang` を付ける。

## 言語切替の着地先（#440との関係）

多言語対応ページでは各言語の同じページを開く。
日本語専用ページの外国語の選択肢は、記憶した言語も含めて `/<locale>/info/guide` に向かい、
既存の「日本語のみ／Visitor Guideへ移動」の注記を表示する。
記憶した言語だからといって `/en/events` のような実在しないURLを作らない。
日本語の選択肢だけは現在の日本語専用ページに留まり、記憶を解除する。

## 検証

`e2e/i18n/locale-persistence.spec.ts` は実ブラウザで以下を検査する。

- en / zh / koで日本語専用ページを経由し、再読み込み後も多言語版へ戻れること（デスクトップ・モバイル）。
- 「日本語」で解除し、再読み込み後も日本語のリンクになること。
- 記憶した外国語の選択肢にも正しいVisitor Guideのリンクと注記があること。
- ブラウザ言語が英語でも未選択なら日本語のままであること。
- `sessionStorage` が拒否されてもクライアント遷移で保持・解除できること。
- 多言語対応ページで別言語または日本語のURLを開くと、そのURLが優先されること。
- 上の遷移・再読み込みでハイドレーションのエラーが出ないこと。

SSR/ハイドレーションの確認は本番ビルドでも実施する。開発サーバーのE2Eだけで判断しない。

2026-10-10の修正前検証では、enのデスクトップ・モバイルの両ケースが
「期待 `/en/access`、実際 `/access`」で失敗し、言語保持の退行を捕まえることを確認した。
