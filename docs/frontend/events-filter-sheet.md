# `/events` のモバイル絞り込み（検索バー＋ボトムシート）

lg 未満の `/events` で、絞り込みが画面の大半を占めて企画カードが見えなくなっていた問題の
対処と設計です（#376）。追従（sticky）そのものの設計は
[events-infinite-scroll.md](./events-infinite-scroll.md)、検索の中身は
[events-search.md](./events-search.md) を参照してください。

## 出発点（2026-10-04 本番実測、390x844）

| 状態                                          | 実測                                     |
| --------------------------------------------- | ---------------------------------------- |
| 閉じたバー（sticky）                          | `<aside>` 約 78px                        |
| 開いた状態（**sticky のまま追従**）           | `<aside>` **612px / 844px**（画面の73%） |
| `?type=stage` で来訪（条件付きURLは自動展開） | 最初のカードが **y=1388px**（画面外）    |

原因は2つ。

1. 開催日・種別・建物・キーワードの4項目を縦に全展開したパネルが、sticky のまま画面上部を占める
2. URL に条件があると自動展開していた（`useState(hasActiveFilters)`）

## 形

| ブレークポイント | 追従するもの                                | 開催日・種別・建物                 |
| ---------------- | ------------------------------------------- | ---------------------------------- |
| `lg` 未満        | キーワード入力＋「条件」ボタン（**73px**）  | ボトムシート（`EventFilterSheet`） |
| `lg` 以上        | サイドバー（キーワードと絞り込みの2カード） | サイドバーに常時表示               |

変更後の実測（dev、実データ、390x844、`?type=stage`）: `<aside>` **60px**（当時。上の余白を 1rem 広げた 2026-10-04 以降は 73px）、
「N 件の企画が見つかりました」が y=792（画面内）。シートは下端に接地し高さ 508px（上限 85dvh）。

| ファイル                                      | 役割                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| `src/components/events/EventFilters.tsx`      | 2つの形を DOM の並び順と表示切替で作り分ける                                 |
| `src/components/events/EventFilterFields.tsx` | 開催日・種別・建物。サイドバーとシートの2箇所に描く                          |
| `src/components/events/EventFilterSheet.tsx`  | シートの中身。外枠は共通部品の `SlidePanel`                                  |
| `src/components/ui/SlidePanel.tsx`            | 開閉（showModal・退場アニメーション・Esc・背景）。タイムテーブル・協賛と共用 |

## 設計判断

### 2つの形を DOM の並び順だけで作る

`EventFilters` のルートは「キーワード → 絞り込みカード（見出し・項目） → 条件ボタン → シート」の順に並ぶ。
lg 未満では絞り込みカードを隠して `flex` の横並びにし、lg 以上では条件ボタンを隠して縦に積む。
lg ではキーワードを**別カード**にする（絞り込みの最下部に埋もれていたため）。`max-h` はルートに置き、
キーワードのカードは `shrink-0`、絞り込みのカードが `min-h-0 overflow-y-auto` で残りを受ける。
**キーワード入力は1要素のまま両方の形で使う。** IME 判定・デバウンス・巻き戻り防止の状態を
二重に持たないため（[events-search.md](./events-search.md)）。

`EventFilterFields` は2箇所に描かれるが、片方は必ず `display: none` なので支援技術には1組しか
見えない。`id` は文書内で一意でなければならないので `useId()` で振る。
**`id="keyword-search"` は固定のまま残す。** `scripts/assert-events-static-html.mjs` が
静的HTMLの目印にしている。

### 選択は即時反映（下書きを持たない）

シートを開いたままでも選んだ瞬間に URL が変わり、背後の一覧と「N 件の企画を表示」の件数が
追従する。0件になる組み合わせに、閉じる前に気づけるようにするため。
意味検索（第4段）の応答待ちでは件数が確定しないので、ボタンは「結果を表示」になる。

### 自動展開をやめ、バッジで知らせる

条件付きURLで来ても開かない。選択中の数は「条件」ボタンのバッジで示す。
**キーワードは数えない**（バーに常に見えているため）。

### 「クリア」はキーワードを消さない

シートの「クリア」は開催日・種別・建物だけを戻す。キーワードはシートの外にあり、
シートの操作で黙って消すと何が起きたのか分からなくなるため。lg のサイドバーの
「リセット」は従来どおり全部戻す。

### 条件ボタンはアイコンだけ

「条件」の文字を添えるとボタンが 102px を取り、390px 幅でも入力欄の文字領域が 106px しか
残らず、プレースホルダ（131px）が途中で切れた。アイコン（44px）にして 192px を確保した。
**320px 幅では 122px で、まだ 9px 足りない**（`例: 9号館のダン` まで見える）。
該当するのは iPhone SE（第1世代）級だけなので許容している。

### lg へ広げたら閉じる

`SlidePanel` は lg 以上で右からのパネルに変形する。開いたまま lg へ広げると、
サイドバーと同じ項目を出す右パネルが残り、`showModal()` の inert でサイドバーも一覧も
操作できなくなる。`matchMedia("(min-width: 64rem)")` の変化で閉じる。

### 読み込み中の骨格も揃える

`src/app/events/(list)/loading.tsx` は lg 未満で細いバーの骨格だけを出す。
全項目の骨格を出すと、読み込みの間だけ 600px 超の塊が画面を占める。

### 絞り込み後のスクロール位置（#392）

絞り込みは `{ scroll: false }` で URL を書き換えるため、スクロール位置は残る。一覧を読み進めた
状態で結果が減ると文書の高さが縮み、ブラウザが `scrollY` を新しい最大値へ切り詰めて、
件数次第で一覧の途中やフッター付近に着地していた。`{ scroll: true }` はページの先頭へ移るだけで、
結果の先頭にはならない。

`EventResults`（結果ブロックを包む client 部品）が、絞り込みの指紋（`buildEventsQuery(filters)`）が
変わったときに**結果の先頭が隠れていれば** `scrollIntoView({ block: "start" })` で寄せる。

- 先頭が見えているとき・初回マウントでは動かさない（ページ上部で打ち始めた来場者の Hero を消さない）
- 意味検索の状態遷移は指紋に含めない（結果が届いた時点で2度目の移動を起こさない）
- 寄せる位置は `scroll-margin-top` が一次定義。lg 未満は追従バーの下端（header + 5px + 3.25rem = 145px）、
  lg 以上はヘッダー + 1rem。JS は計算値を読んで「隠れているか」の判定にだけ使う。
  **aside の寸法を変えたらこの値も合わせる**
- `EventsView` は Server Component からも fallback として描かれ hooks を持てないため、部品を分けている

実データ（390x844、99件の位置 y=2470 から「ダンス」で2件）で、件数表示が追従バーの直下 145px に来ることを確認した（2026-10-04）。

## 検証

`e2e/events/responsive-parity.spec.ts`（mobile project 320x640。lg のケースだけ 1280x900）。
**企画の件数に依存させていない**（Layout E2E は microCMS の資格情報を持たず、一覧が0件になる）。
追従の検査に要る高さは一覧の側へ足している。

退行を注入して赤くなることを確認した（2026-10-04）。

| 注入                                                | 赤くなったテスト                      |
| --------------------------------------------------- | ------------------------------------- |
| `useState(sheetFilterCount > 0)`（自動展開を戻す）  | 条件付きURLでも開かない、ほか2本      |
| 条件ボタンの `lg:hidden` を外す                     | lg 以上でシートの入口が出ない         |
| サイドバー項目の `hidden` を外す（lg 未満で全展開） | 条件付きURLでも開かない（バーの高さ） |

`e2e/events/results-scroll.spec.ts`（mobile project。lg のケースだけ 1280x900）は絞り込み後のスクロール位置を見る。

| 注入                                      | 赤くなったテスト                              |
| ----------------------------------------- | --------------------------------------------- |
| `scrollIntoView` を外す                   | 読み進めた状態で検索（lg 未満・lg 以上の2本） |
| 「隠れているときだけ」の条件を外す        | 結果の先頭が見えているときは動かさない        |
| lg 未満の `scroll-mt` から `5px` を落とす | 読み進めた状態で検索（lg 未満）               |

資格情報あり（実データ）と、資格情報なし（CI と同じ0件）の両方で全 e2e が緑。
