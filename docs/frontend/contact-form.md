# お問い合わせフォーム（`/info/contact` と `/api/contact`）

送信の可否をどう判断しているかと、そう決めた理由をまとめる（#260 / #261）。

## 出発点: 本番で1通も送っていなかった

2026-09-21、本番の `/api/contact` は次を返していた。

```
{"success":true,"message":"お問い合わせを受け付けました（開発モード）"}
```

`SMTP_*` と `CONTACT_TO_EMAIL` が **Production / Preview / Development のどこにも無く**、
内容は関数ログへ `console.log` されるだけだった。にもかかわらず来場者には
「**送信完了 / お問い合わせを受け付けました。3営業日以内にご返信いたします。**」と緑で出ていた。

**種別に「落とし物のお問い合わせ」を含む。** 当日の届け出がそこで消える状態だった（#261）。

## 設定が欠けていたら、成功を返さない

判断は `decideMailerAction()`（`src/lib/contact-guard.ts`）が持つ。**純粋関数なのでテストで縛れる。**

| 戻り値      | 状況                       | 応答                           |
| ----------- | -------------------------- | ------------------------------ |
| `"send"`    | 設定が揃っている           | 送信して 200                   |
| `"reject"`  | **本番で設定が欠けている** | **503。X のDMへ誘導する**      |
| `"dev-log"` | 本番以外で欠けている       | ログへ出して 200（開発の利便） |

> [!WARNING]
> **本番で `"dev-log"` を返してはいけない。** これが #261 そのものである。
> 退行を注入するとユニットテストが落ちる。

**503 の文言に「時間をおいて再度お試しください」と書かない。** 待っても直らない。
代替の連絡手段（X `@setagayafes_tcu` のDM）を案内する。

### 必要な環境変数

`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `CONTACT_TO_EMAIL`。
1つでも欠けたら送らない。**欠けている名前をログへ出す**ので、Functions ログを見れば分かる。

- **`CONTACT_TO_EMAIL` に既定値を置かない。** 以前は `contact@setagayafes.com` へ落ちていたが、
  このサイトのドメインは `setagayafes.org` であり、**届かない先へ静かに送る**形だった
- **差出人は `CONTACT_FROM_EMAIL || SMTP_USER`。** 別ドメインの既定値を書くと SPF / DMARC で弾かれる
- `SMTP_PORT=465` のときだけ SSL/TLS で張る（587 は STARTTLS なので `secure: false`）

## 画面（`/info/contact`）

### 種別カードは飾りではなく選択そのもの

以前は3枚の説明カードを並べたうえで、フォーム側の `<select>` に同じ3件をもう一度置いていた。
来場者は同じ選択肢を2度読み、**カードのほうは押しても何も起きなかった。**
現在はカードが `<input type="radio">` を内包し、選択中のカードだけが藤色で塗られ、
下向きの角でこの下のフォームを指す。

> [!IMPORTANT]
> **`<select>` を戻さないこと。** 送信ペイロードの `type` は変わっていないので、
> 戻しても型もテストも通る。**重複が復活するだけで誰にも気づかれない。**

`<input>` は `sr-only` で視覚的にだけ隠す。`hidden` や `display: none` にすると
**キーボードでも読み上げでも到達できなくなる。** フォーカスリングは `peer-focus-visible:`
で `<span>` 側へ出す。

### 入力欄にホバーの背景色を書かない

`src/app/[locale]/info/contact/ContactForm.tsx` の `FIELD_CLASS` に
**`hoverable:hover:bg-*` を書いてはいけない。** `aria-[invalid=true]:bg-*` と
同じ `background-color` を争い、**入力漏れの欄にカーソルが乗っているあいだだけ
赤い面が消える**（2026-09-22 実測）。lint も型もテストも通る。

勝敗を決めているのは詳細度ではなく**出力順**である。5つとも `.cls:hover` /
`.cls[aria-invalid="true"]` で詳細度は (0,2,0) であり、後に出たほうが勝つ。
出力CSSのバイト位置（2026-09-22 / standalone postcss で実測）:

| 位置 | ユーティリティ                       |
| ---- | ------------------------------------ |
| 4855 | `focus:border-primary-600`           |
| 4956 | `focus:bg-white`                     |
| 5045 | `aria-[invalid=true]:border-red-600` |
| 5170 | `aria-[invalid=true]:bg-red-50`      |
| 5304 | `hoverable:hover:bg-primary-100`     |

つまり **`aria-*` は `focus:` に勝ち、`hover:` に負ける。**

> [!WARNING]
> **`focus:border-*` は `aria-invalid` の赤い境界線を隠さない。**
> 本ファイルには 2026-09-22 まで「隠す」と書かれていたが誤りで、上の実測が反証する。
> 誤診の原因は、`focus-visible:outline-3 outline-primary-600` が描く**3px の紫の
> アウトラインを境界線と読み違えた**こと。`FIELD_CLASS` から `focus:border-*` を
> 外しているのは「アウトラインと二重になって情報が増えない」ためであり、
> アクセシビリティ上の必須事項ではない。

### 必須ではなく任意のほうに印を付ける

6欄のうち**任意なのは電話番号だけ**である。赤い `*` を5箇所に置いて末尾に凡例を添えるより、
例外1つに「任意」と書くほうが読む量が減る。機械向けには各欄の `aria-required="true"` が伝える。

**`*` を戻すなら、凡例も一緒に戻すこと。** 印だけ戻すと、意味を説明する場所がどこにも無くなる。

### 白文字を `bg-primary` の上に置かない

ブランドカラー実配信 `#bf73e3` と白のコントラストは **3.10:1** で AA に届かない
（[design.md](./design.md)「ブランドカラー」が明記している）。送信ボタンは
`bg-primary-600`（`#7b359a` / 7.45:1）、選択中の種別カードは `bg-primary-700`
（`#592072` / 11.2:1）を使う。

> [!NOTE]
> **同じ誤りが他に6箇所残っている**（2026-09-22 時点。`privacy` / `faq` /
> `FeaturedCarousel` / `SponsorModal` / `TicketTable` / `ComingSoon`）。
> このページの修正には含めていない。

## 自動投稿よけが主防御、IP 制限は補助

`/api/contact` は**メールを送る口**で、1通ごとに SMTP の送信枠と委員会の受信箱を消費する。

| 層  | 実装                                                 | 状態 | 効き方                           |
| --- | ---------------------------------------------------- | ---- | -------------------------------- |
| 主  | `src/lib/contact-guard.ts`（ハニーポット・経過時間） | 無   | **どのインスタンスでも同じ判定** |
| 補  | `src/lib/rate-limit.ts`（30本/分・IP）               | 有   | 素朴な連打を鈍らせるだけ         |

> [!IMPORTANT]
> **IP 単位の制限は厳密な上限にならない。** サーバーレスでは状態がインスタンスごとに別で、
> 2026-09-21 の実測では **429 を返した約3秒後に、上限を超えたはずの同じIPが通った**（#260）。
> 実効の上限は「設定値 × 同時に生きているインスタンス数」で、**負荷が上がるほど緩くなる。**
> だから状態を持たない検査を主防御に置く。

**30本/分は「1人あたりの妥当な回数」ではない。** 学園祭当日は大学構内の Wi-Fi から数千人が
同じ出口IPで出てくる。1人基準（数本/分）で置くと、**落とし物を届け出ようとした来場者が、
自分ではなく他人の送信で弾かれる。** 誤爆を避ける側へ倒してある。

なお **`x-forwarded-for` は詐称できない**（Vercel が上書きする。実測済み）。限界は詐称ではなく、
NAT と、この状態の非共有である。

### ハニーポットと経過時間

| 検査           | 落とすもの                             | 誤爆の可能性                                      |
| -------------- | -------------------------------------- | ------------------------------------------------- |
| ハニーポット   | 隠し欄を埋める自動投稿                 | ブラウザの自動入力（`autoComplete="off"` で軽減） |
| 経過時間 3秒   | 描画直後に送る自動投稿                 | 人には到達しない                                  |
| 経過時間の欠落 | **ページを描画せず直接 POST する相手** | 無し（正規のフォームは必ず送る）                  |

**隠し欄は `aria-hidden` と `tabIndex={-1}` の両方で隠す。** 片方だけだと、
スクリーンリーダーの利用者や Tab で辿る人が「入力してはいけない欄」に到達する。
`display: none` ではなく画面外へ飛ばすのは、そのほうが自動投稿に埋められやすいためである。

**拒否したときの案内は「再読み込み」を促す**（`RETRY_HINT`）。自動入力の誤爆で弾かれた人が
自力で復帰できる必要がある。**「時間をおいて」と書くと、待っても直らないのに待たせることになる。**

## 検証

### 副作用なしにレート制限を試せる

**空ボディ `{}` を POST すると 400 で終わり、メールは出ない。** レート制限は本文のパースより
**前**に走るので、これで上限だけを試せる。

```bash
for i in $(seq 1 35); do
  curl -sS -o /dev/null -w '%{http_code} ' -X POST -H 'Content-Type: application/json' \
    --data '{}' https://setagayafes.org/api/contact
done
# 30本目まで 400、31本目から 429 になる
```

**この性質を壊さないこと。** 検証の順序を変えて本文のパースを先にすると、この手が使えなくなる。

### 本番で「届いているか」を見る

応答の `message` が経路を表す。**外から判別できる。**

| `message`                                    | 意味                         |
| -------------------------------------------- | ---------------------------- |
| `お問い合わせを受け付けました`               | **送信した**                 |
| `お問い合わせを受け付けました（開発モード）` | 本番では出ない（出たら事故） |

成功時は `[contact] 送信しました type=... len=...` を1行残す。
**氏名・メールアドレス・本文はログへ出さない。** 種別と本文の長さがあれば量と傾向は追える。

### 退行注入（2026-09-21 実測。すべて赤くなる）

| 注入した退行                                       | 落ちるテスト |
| -------------------------------------------------- | ------------ |
| 本番でも `dev-log` を返す（**#261 そのもの**）     | 1本          |
| ハニーポットの検査を外す                           | 2本          |
| 経過時間の検査を外す                               | 1本          |
| 直接 POST（経過時間なし）を通す                    | 1本          |
| 下限を 3秒 → 10秒 へ上げる（人を弾く側へ行きすぎ） | 1本          |
| 拒否の案内を「時間をおいて」へ戻す                 | 1本          |

### 偽の SMTP で送信経路を確かめる

本番の資格情報を使わずに、送信そのものを確かめられる。2026-09-21 に実施し、
`MAIL FROM` が `SMTP_USER`、`RCPT TO` が `CONTACT_TO_EMAIL`、`Reply-To` が来場者のアドレスに
なることを確認した。手順は `docs/dev/testing.md` の方針どおり、**使い捨てのスクリプトで行い、
リポジトリへは残していない**（最小のSMTPサーバーを立てて `next start` の環境変数を差し替えるだけ）。
