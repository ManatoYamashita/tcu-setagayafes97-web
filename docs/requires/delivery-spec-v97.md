本仕様書は、第97回世田谷祭公式ホームページの開発にあたり、業務内容および成果物等を明確化することを目的として作成したものです。

## 1. 業務目的

学園祭ホームページのデザイン及び操作性を改善し、来場者への情報発信の充実と実行委員会の更新作業の効率化を図ります。具体的には以下を目的とします。

- 来場者に学園祭の情報をわかりやすく提供する
- 企画の検索・発見を容易にし、来場者体験を向上させる
- 3Dマップ（実装難易度が高い場合は2Dマップにフォールバック）による直感的な会場案内を実現する
- 多言語対応（日本語／英語／中文簡体字／韓国語）により、留学生・外国人来場者にも情報を提供する
- microCMSの導入により、実行委員会自身が専門知識なしに更新作業を行える体制を構築する

## 2. 対象範囲

世田谷祭公式ホームページ全体（PC版およびスマートフォン版）

- 対応ブラウザ：Chrome／Safari／Firefox／Edge（最新2バージョン）、iOS Safari（iOS 16.4以上）、Android Chrome（最新）
- ホスティング：Vercel（Free Plan）

> **注記（2026-08-29 改訂）**
> 対応ブラウザの下限を iOS 15 から **iOS 16.4** へ改めた。
> 下限を決めているのは実装ではなく TailwindCSS v4 の要求
> （Safari 16.4 / Chrome 111 / Firefox 128）であり、`@property` と `color-mix()` に依存する。
> 引き下げるには TailwindCSS v3.4 へのダウングレードが必要になる。
> **本書を実行委員会へ提出済みの場合、提出版との差異について確認および差し替えの要否を判断すること。**

## 3. 業務内容

- ホームページ全体のデザインリニューアル
  - 世田谷祭のブランドイメージ（テーマカラー `#CD79EE`）に沿ったデザイン設計
  - 配色・フォント・レイアウトの見直し（デザイントークンとして `docs/frontend/design.md` に文書化）
  - 各ページの統一感のあるUIデザインの作成
- サイト構造・導線設計

  - 企画検索・一覧ページ（日程／場所／カテゴリ／キーワードでの絞り込み）
  - タイムテーブルページ（Day1／Day2切替、ステージ別タブ）
  - マップ・アクセスページ（3D／2Dキャンパスマップ、交通アクセス）
  - インフォメーション（お知らせ一覧・詳細、ご来場の方へ、FAQ、パンフレットDL、お問い合わせ）
  - 委員会・その他（委員長挨拶、協賛企業一覧、プライバシーポリシー）
- スマートフォン表示への最適化（モバイルファースト設計）
- ユーザーが目的の情報へアクセスしやすい導線設計（ヘッダーナビゲーション、フィルターUI）
- microCMSを用いたCMS基盤の構築（お知らせ・企画・協賛情報を実行委員会が自ら更新できる仕組み）
- 多言語対応の実装（固定ページのみ、next-intl等を使用）
- お問い合わせフォームの実装（一般・取材・落とし物の3種別）
- SEO対策（メタタグ、構造化データ、sitemap.xml、robots.txt）およびアクセシビリティ対応（WAI-ARIA、キーボード操作、カラーコントラスト）

## 5. 世田谷祭実行委員会での可能な操作

改修後のホームページにおいて、実行委員会は管理画面（microCMS管理画面）を通じて以下の更新・編集操作を行うことができるものとします。

**（1）お知らせ機能**

- お知らせ記事の新規作成・編集・削除
- 文章および画像の追加・差し替え
- 種別（緊急／通常／その他）の設定
- 必要に応じた公開・非公開の設定

**（2）企画紹介ページ**

- 各企画内容（文章・画像・開催日程・場所・時間等）の編集・更新
- 企画ごとの情報の追加・修正・削除

**（3）インフォメーション（協賛企業情報等）**

- 協賛企業情報（企業名・ロゴ・リンク等）の追加・編集・削除
- 表示順の変更（優先度フィールドによる並び替え）

**（4）掲載コンテンツについて**

ホームページに掲載する文章・画像等のコンテンツは、原則として実行委員会が用意し、開発担当へ提供するものとします。
開発担当は、提供された素材を用いて各ページへの反映および必要な調整（サイズ調整・レイアウト調整等）を行います。

## 6. 改善目標

本件における「改善」とは、昨年度WEB担当の振り返りにおいて課題として挙げられていた以下の点の解消を指すものとしております。

- デザイン面において、技術的制約等により十分なデザイン性を確保できなかった点
- 編集作業において、更新・編集が行いづらい構造であった点
- ホームページ全体の操作性（UI/UX）が低く、利用者および運用者双方にとって扱いづらかった点
- Wordpressの脆弱性に対応できていない点
- パフォーマンスが低くアクセシビリティの担保がされていない点

これらの課題を踏まえ、以下をもって「改善」を実現します。

- モダンな技術スタック（Next.js／TailwindCSS／GSAP／Three.js/Vercel）の採用によるデザイン表現力・パフォーマンスの向上
- microCMS導入によるノーコードでの更新・編集性の向上
- モバイルファースト設計・統一感あるUIによる操作性（UI/UX）の改善
- フルスタック開発による開発の自由化
